# 设计模式面试口述（okx-bot）

读法：每一种模式都是 **先搞懂模式本身，再看项目里怎么用，最后才是开口稿**。  
类图和文件名见 [`后端设计模式落地说明.md`](./后端设计模式落地说明.md)。

项目一句话：Spring Boot 后端，做视频提取、成片、文生图、文章提取。外面接 TTS、Whisper、Remotion、FLUX、对象存储，协议都不一样。

---

## 1. 适配器模式 / 六边形架构（Adapter，Ports & Adapters）

### 这种模式是什么

业务心里只认「我要配音」「我要存文件」，不认「Edge-TTS 命令行怎么拼」「S3 SDK 怎么调」。

中间放一个 **接口（Port）**：方法名是业务语言，比如 `synthesize(文案)`。  
外面再写 **适配器（Adapter）**：把业务调用翻译成某个厂商、某条命令行、某套 HTTP。

换厂商、本机 mock、云上 R2，都是换 Adapter。业务代码不改。

和「策略」容易混：策略是「明确选一种算法」；适配器强调的是 **挡住外部世界的形状**，让内核干净。

### 项目里怎么用

成片流水线只依赖接口：

| 业务要做的事 | 接口 | 外面真实在干什么 |
|--------------|------|------------------|
| 配音 | `TtsPort` | Edge-TTS / Windows 语音 / 假音频 |
| 出分镜 | `ScriptPlanPort` | LangChain4j 或旧 OkHttp |
| 渲染成片 | `VideoRenderPort` | Remotion HTTP 或假 mp4 |
| 存产物 | `ObjectStoragePort` | 本地磁盘或 Cloudflare R2 |
| 发博客 | `HaloPublishPort` | Halo HTTP，或未配置时的 Disabled |

启动时 `AigenBeanConfig` 按配置把实现接到接口上。步骤类只注入 Port，不 import 厂商 SDK。

视频理解同样：Mock、Omni、抽帧都实现 `VideoUnderstandingPort`，Router 按 protocol 选。Service 只切时间窗、拼结果。

知识库、登录没有第二套协议，就没有硬套这层。

### 开口可以说

> 我们把外部依赖收成端口。流水线只调「配音、渲染、存储」，真正调 Edge-TTS、Remotion 的代码在 Adapter 里。本机没装工具就接 Mock，上云把存储换成 R2，步骤代码不用改。

## 2. 策略模式（Strategy）+ 注册表

### 这种模式是什么

同一件事有多种做法，调用方不想写一长串 if。

先定一个 **策略接口**（做什么：下单、验签）。  
每种做法一个 **实现类**。  
再用一张 **表（Registry）**：用名字取出对应实现。

以后多一种做法，加一个类、注册进去。订单服务、对话编排不用改。

### 项目里怎么用

**支付。** Mock 充值、支付宝扫码/H5、以后微信，下单和验签协议完全不同。接口是 `PaymentChannel`：`createPayment`、`parseAndVerifyNotify`、`queryPayment`。`PaymentChannelRegistry` 按 `channelId` 取通道，并看配置开没开。微信枚举已经留了，进件后加 `WechatPaymentChannel` 即可。

**对话 Agent 工具。** 模型只能调白名单。每个工具实现 `AgentTool`（名字、说明、风险、execute）。`ToolRegistry` 启动时收集。读工具直接跑；写工具只出确认草案，用户点了才真正创建任务——所以不能换成框架自动调工具。

### 开口可以说

> 支付渠道是策略：同一套「下单、验签、查单」，Mock 和支付宝各写一个实现，订单服务只问注册表要渠道。Agent 工具也是，按名字取，写操作必须用户确认。

## 3. 组合模式 / 责任链（Composite，短链回退）

### 这种模式是什么

对外还是 **一个接口、一次调用**。对内不是只跑一家，而是 **按顺序试**：先专用的、更好的；不行再通用的、保底的。

教科书里的组合常常是树（文件夹里还有文件夹）。我们用的是它的窄版：**一条短链**，失败就下一个。也叫责任链。

适合「更好的方案不稳定，但必须有一个能用的」。

### 项目里怎么用

三处都是「好方案经常挂」：

1. **文章抓取** `CompositeArticleFetchAdapter`：先问头条适配器认不认这个链接；不认再走通用 HTML。构造器里显式传入两个实现，避免 Composite 把自己再注入进去。
2. **图生视频** `CompositeImageToVideoAdapter`：先 NVIDIA SVD，失败用本地 kinetic 镜运动效，镜头至少还有画面。
3. **配音** `AutoTtsProvider`：先 Edge-TTS，失败用 Windows 自带语音，还不行且开了 fail-open 就 Mock，避免整单卡死。

视频理解 Router 也是：Omni 媒体失败再抽帧。

### 开口可以说

> 对外一个「抓取」「配音」，对内按优先级试。专用失败就通用，云端失败就本地保底。调用方不用自己写重试顺序。

## 4. 工厂模式（Factory）

### 这种模式是什么

有些对象 **不好 new**：要读密钥、校验证书、选超时、按用户选配置。

把「怎么造出来」收到 **工厂** 里。别人只说「我要这个供应商的这个模型」，不自己拼 SDK。

常见三种（面试能分清即可）：

- **简单工厂**：一个类里根据参数 return 不同对象。我们的 `ChatModelFactory` 接近这种。
- **工厂方法**：不同创建者造不同产品。`HaloClientResolver` 按超管/普通用户 resolve 出不同客户端，接近这种。
- **抽象工厂**：一次换一整族产品。我们没有产品族，没用。

Spring 的 `@Bean` 也是工厂，适合进程里唯一或启动时二选一的对象。

### 项目里怎么用

- **`ChatModelFactory`**：每个任务可以换供应商、模型、超时。测试连通性要短超时，正式生成可能 180 秒，所以不能全局一个 ChatModel 单例。工厂读 `ai.providers`，把 base-url 归一化到 `/v1`，再按这次参数构建。
- **`AlipayClientFactory`**：PEM 密钥格式、沙箱还是正式。
- **`HaloClientResolver`**：超管用平台 yml 令牌；普通用户必须自绑博客，每次 new 一个 HTTP 适配器。
- **`AigenBeanConfig` 等**：启动时决定 Port 接 Mock 还是真实现，不是在 Pipeline 里 if mock。

### 开口可以说

> 聊天模型按任务参数现造，密钥和超时都在工厂里。Halo 按当前用户造客户端。对象存储这种进程级二选一，用 Spring `@Bean` 当工厂就够了。

## 5. 门面模式（Facade）

### 这种模式是什么

子系统很复杂（重试、超时、流式、两套引擎），但调用方只想要一个简单动作：`chat(系统提示, 用户话, 模型)`。

门面就是 **对外一扇门**，把里面的乱收起来。换内部实现，门上的方法不变。

和适配器的差别：适配器是「把外面的怪协议收成我们的接口」；门面是「对内几套实现，对外一个简单 API」。

### 项目里怎么用

总结、分镜、润色、文章 CORE、对话，都要走 OpenAI 兼容 Chat。以前手写 OkHttp，后来切 LangChain4j，还要能一键回滚。

业务统一调 `LlmChatClient`：

- 默认进 `LlmChatGateway`（LangChain4j）
- 配置 `ai.chat-engine=okhttp` 走旧客户端

重试、流式空闲超时都在门面里。TTS、Remotion、FLUX 生图 **不走这扇门**，协议不是 Chat。

### 开口可以说

> 对业务只暴露 chat。里面可以是 LangChain4j 或 OkHttp，一个配置切换。换引擎不用改总结和分镜代码。

## 6. 空对象 / 假实现（Null Object，Mock Adapter）

### 这种模式是什么

接口必须有实现，但有时「没配、没装、不能调真服务」。

不要在每个调用点写 `if (没配置) return`。写一个 **合法实现**：要么明确拒绝并给文案（空对象），要么返回能把流程走完的假数据（Mock）。

调用方始终当接口可用。

### 项目里怎么用

本机经常没 edge-tts、没 Remotion、没 Halo 令牌，但前端仍要看任务从排队到成功。

- **Mock**：假分镜、假配音、假成片、假出图、假画面理解。`mock-pipeline=true` 就能跑通状态机。这是给演示和联调的 **产品能力**，不是单测里的 Mockito。
- **DisabledHaloPublishAdapter**：没配博客时发布会得到稳定错误，而不是空指针。
- TTS 还可 fail-open 到 Mock：配音挂了也能出片。

### 开口可以说

> 没装外部工具时，接口仍然有实现：要么假数据把 UI 走通，要么 Disabled 给出明确失败。步骤代码里没有一堆 if 没配置。

## 7. 命令对象（Command，我们只用了「参数对象」这一层）

### 这种模式是什么

完整命令模式可以把「一次操作」做成对象，拿去排队、撤销、重放。

我们 **只用了其中最薄的一层**：把一次出站调用的参数收成一个对象，避免方法参数越来越长，也避免 Adapter 直接依赖数据库实体。

不要在面试里说自己做了撤销、宏命令——项目里没有。

### 项目里怎么用

`TtsCommand`、`ArticleFetchCommand`、`ImageGenCommand`、`VideoUnderstandingCommand` 等。Port 的方法是 `fetch(命令)`，不是 `fetch(url, 平台, 超时, 用户代理, …)`。

步骤从任务实体上取出字段，组成 Command 再交给 Port。Adapter 不知道有没有 `AigenTaskEntity`。单测也可以只构造命令。

### 开口可以说

> 出站参数打成 Command，端口不依赖任务表。我们没有做命令队列和撤销，就是把一次调用说清楚。

---

## 8. 模板方法（Template Method）+ 策略选步

### 这种模式是什么

**模板方法**：骨架写在父类或一个流水线类里——先更新状态、再执行一步、再记耗时、再通知前端。变化的部分交给子步骤自己实现。

每一步看起来像策略：同一个 `execute`，不同步骤不同算法。  
另外还可以用策略 **决定跑哪些步**（有的模式不转写、不理解画面）。

暂停杀不掉正在跑的 ffmpeg，所以只在 **步骤交界** 停，这正好配模板方法的「步骤边界」。

### 项目里怎么用

四套异步任务都是「外壳循环 + 步骤实现」：

| 模块 | 步骤 |
|------|------|
| 成片 | 规划 → 素材 → 渲染 |
| 文生图 | 润色 → 出图 |
| 视频提取 | 下载 →（转写）→（理解）→ 总结，由 `UnderstandingMode` 选步 |
| 文章 | 解析 → 抓取 → 抽正文 → CORE → 改写；`ArticleFetchPolicy` 决定跳过抓取或进入「请粘贴」 |

超长 hybrid 视频会由 `OmniDurationGuard` 降成纯音频，后面理解步自动不跑。

调度占槽、暂停/取消标记复制了四遍，抽成 `TaskSlotKernel`。每个 Scheduler **自己 new 一份**，不能全局一个，否则视频会占成片的槽。查库、孤儿任务标失败，仍留在各模块，因为状态枚举不同。

没有做成 `AbstractPipeline<T>`：文章有「等用户粘贴」，和视频、成片差太多，框架会更贵。

### 开口可以说

> 流水线骨架固定：改状态、跑一步、记耗时、推 SSE。每步自己实现。视频用模式选要不要转写和理解画面。四套任务的占槽抽到内核，但没有做成万能流水线基类。

## 9. 观察者模式（Observer）

### 这种模式是什么

对象状态变了，要通知一群关心的人，而且人数会变（用户打开或关掉页面）。

被观察者 **发出通知**，观察者 **自己来订阅**。不必 3 秒问一次「好了没」。

浏览器场景里，观察者就是这条 SSE 连接。Spring 内部 `ApplicationEvent` 到不了浏览器，所以用 `SseEmitter`。

多进程以后会变成发布订阅（Redis）。现在是单机观察者。

### 项目里怎么用

任务步骤可能跑几分钟，前端要近实时；没任务时不该空转打列表。

以前四个 `*TaskEventPublisher` 从视频那份拷出来。连接上限、心跳、用 TEXT_PLAIN 发 JSON（避免被再包一层引号）四处各写一遍。

现在 **`UserSseHub`** 管连接和心跳。各 Publisher 只把实体收成轻量字段。用 channel（video / aigen / article / imggen）分桶，成片页不会收到视频提取事件。视频历史只有 `taskId`，其它模块多一个 `id`，Hub 用参数保持线格式。

### 开口可以说

> 任务状态变了主动推给已打开页面的用户。连接在一个 Hub 里，四个工具按频道隔离。这是观察者；以后多实例再在 Hub 后加 Redis。

## 10. 被问「项目用了哪些模式」——1 分钟

按 **问题 → 模式** 说，不要报菜名：

1. 外部协议乱 → **适配器 / 端口**，流水线不绑厂商。  
2. 支付、工具要可加 → **策略 + 注册表**。  
3. 好服务不稳定 → **短责任链**（TTS、抓取、Omni 回退抽帧）。  
4. 模型、Halo 客户端难 new → **工厂**。  
5. Chat 要切引擎还要回滚 → **门面**。  
6. 本机没工具 → **Mock / 空对象**。  
7. 异步任务步骤像、占槽像 → **模板方法 + 槽内核**；状态用 **观察者 SSE** 推前端。

收尾：

> 命令只做参数对象，没有撤销。知识库和登录没有套这些，没有第二套实现就先不抽象。

## 11. 临场

- 先说人话里的问题，再贴模式名字。  
- 每种举 **一个** 类：`TtsPort`、`PaymentChannelRegistry`、`UserSseHub`。  
- 「策略还是适配器」用职责回答：挡住外部形状的是适配器；同一业务多种算法按 id 选的是策略。  
- 主动说没做什么，比再报三个名字加分。
