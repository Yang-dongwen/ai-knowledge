# 视频核心内容提取 — 功能拓展与优化建议

> 基于当前已实现的一版能力（URL → 下载 → Whisper → LLM，任务列表/详情/暂停重试、模型选择、权限体系等）整理。  
> 目标：体验更好、适配更多场景，可作为后续迭代 backlog 参考。  
> 整理日期：2026-07-13

---

## 1. 现状一句话

已经具备可用的 **单用户 MVP**：

- 粘贴链接 → 异步流水线 → 要点 / 章节 / 导图 / 二创 / 转录 + 播放 seek  
- 暂停 / 重试、步骤耗时、LLM 模型选择与（超管）模型管理  
- 任务按用户隔离，登录鉴权  

还不是 **多场景产品平台**：

- 输入形态单一（仅 URL）  
- 长视频理解存在截断  
- 二创形态单一  
- 下载强依赖主机环境（yt-dlp / FFmpeg / Cookie）  
- 无配额 / 协作 / 导出体系  

### 1.1 当前流水线与状态

| 状态 | 含义 |
|------|------|
| `PENDING` | 排队 |
| `DOWNLOADING` | yt-dlp + FFmpeg |
| `TRANSCRIBING` | Whisper 转录 |
| `SUMMARIZING` | LLM 结构化总结 |
| `SUCCESS` | 成功结束 |
| `FAILED` | 失败（`errorMessage`） |
| `PAUSED` | 用户暂停（需重试继续） |

固定顺序：`Download → Transcribe → Summarize`。  
并发：全局约 2 路（调度器硬编码），非按用户公平。

### 1.2 当前主要产物

- 视频流播放、分段转录  
- 核心要点、章节大纲、思维导图 Markdown、二创脚本  
- 步骤耗时：下载 / 转录 / 总结 / 总计  

### 1.3 相关代码与文档

| 层 | 路径 |
|----|------|
| 后端包 | `src/main/java/com/dwcode/okxbot/video/` |

## 2. 体验上建议优先改的（高价值、成本可控）

### 2.1 提交门槛与进度感知

| 现状 | 问题 | 优化方向 |
|------|------|----------|
| 必须先「测试可用性」才能创建 | 多一步摩擦；模型已配置时多余 | 默认「最近成功模型可直接用」；测试改为可选或后台预检 |
| 3s 轮询 | 列表抖、不够实时 | SSE/WebSocket 推状态；至少区分 PENDING / 排队位次 |
| 暂停只在步骤边界生效 | 长下载/转录时点暂停仍要等很久 | UI 标明「将在当前步骤结束后暂停」；后续支持 kill 子进程 |
| 失败只看 errorMessage | 用户不知该重试还是换 Cookie/模型 | 错误分类 + 对应操作建议（见下） |

**错误分类建议：**

- 网络 / 超时  
- 平台登录墙 / Cookie 失效  
- 视频时长超限  
- Whisper 服务不可用  
- LLM 限流 / 供应商故障  
- 工具缺失（yt-dlp / FFmpeg）  

### 2.2 失败与重试更「省时间」

当前 **Retry = 清空任务目录后全量重跑**（下完又下、转完又转）。

更适用的策略：

1. **断点续跑**：下载成功 → 只重转写；转写成功 → 只重总结  
2. **改模型只重总结**（成本最低，二创/导图场景最常见）  
3. **部分成功**：总结失败时仍展示转录 + 可单独「重新 AI 提炼」  

### 2.3 结果区可用性

**已有：** Tab、复制、时间戳 seek、转录搜索。

**可补：**

- 一键导出包：SRT / VTT、Markdown 笔记、JSON、zip  
- 思维导图真正渲染（Mermaid 预览，而不只 Markdown 文本）  
- 要点/章节 → 勾选生成「剪辑清单」或「提词卡」  
- 任务标题可改、加标签（学习 / 二创 / 会议）  

### 2.4 平台下载稳定性（抖音 / 小红书刚需）

代码侧仅有平台识别，**没有 Cookie / 登录态产品化**。

建议：

- 用户侧上传 / 粘贴 Cookie（或浏览器扩展同步）  
- 按平台失败文案：「需登录态 / 地区限制 / 链接过期」  
- 后台定期校验 yt-dlp 版本与 cookies 有效期  

### 2.5 模型与费用心智

- 去掉「每次必测」后，提交时显示预估：短视频约 1–2 分钟 / 长视频更久  
- 展示历史任务用的模型与耗时，方便选「快 / 准」  
- `MEMBER` 与 `USER` 若差异化：并发数、时长上限、可用模型档位

## 3. 多场景能力拓展

### 3.1 短视频运营（抖音 / 小红书 / TikTok）

**已有：** 链接、平台角标、通用二创脚本。

**建议拓展：**

1. 多平台文案模板：小红书种草体 / 抖音口播 / B 站简介 / 微博 / 标题 5 选 1  
2. 结构模板：钩子 → 痛点 → 干货 3 点 → CTA  
3. 批量链接（剪贴板多 URL、队列可视化）  
4. 竖屏预览、封面帧 / 关键帧（FFmpeg 抽帧）  
5. 标签、话题词、emoji 强度开关  

### 3.2 长视频 / 课程 / 播客

**已有：** 约 2h 上限、章节、分段转录。

**瓶颈：** 总结侧对转录约 **2.4 万字截断**，中间内容易丢。

**建议：**

1. 分块转录 + Map-Reduce 总结（分段摘要 → 总摘要）  
2. 说话人分离（会议 / 访谈）  
3. 更长上限分档：会员 2h / 4h  
4. 「仅字幕 / 仅总结」模式，跳过视频保留以省磁盘  
5. 章节自动生成「学习大纲 + 复习问题」  

### 3.3 学习笔记 / 知识管理

**已有：** 要点 + 章节 + 思维导图 Markdown。

**建议：**

1. 闪卡 / 测验题生成  
2. 双语对照（ASR 语言与输出语言解耦：听中文 → 输出英文笔记）  
3. 导出 Notion / Obsidian 友好 Markdown  
4. 引用溯源：要点旁链到原文时间戳（可点击）  

### 3.4 内容二创 / 剪辑

**已有：** 单一 `repurposeScript`。

**建议：**

1. 多版本：30s 口播 / 60s / 图文长文  
2. 「高能片段」列表（关键词或 embedding 打分）+ 时间码  
3. 脚本分镜（画面建议 + 旁白）  
4. 品牌语气：简洁 / 专业 / 俏皮  

### 3.5 团队 / 多租户（后期）

**已有：** 任务按 `user_id` 隔离。

**建议：** 工作区共享、只读链接、管理员看全站任务、每人并发与配额、用量统计。

## 4. 输入与流水线形态（扩大适用面）

| 能力 | 价值 | 说明 |
|------|------|------|
| **本地上传** mp4 / mp3 / m4a | 极高 | Zoom 录屏、线下课、无公网链接内容 |
| 粘贴纯文本 / 已有字幕 | 中 | 跳过下载 + ASR，只做 AI 结构化 |
| 播放列表 / 合集 | 中 | B 站多 P、系列课批量 |
| 音频优先模式 | 高 | 只要 ASR，不存大视频，省盘省时间 |
| 可选跳过步骤 | 高 | 只要字幕 / 只要总结 / 只要二创 |

当前流水线固定 `Download → Transcribe → Summarize`，做成 **可配置步骤** 会立刻覆盖更多场景。

## 5. 工程与稳定性

| 项 | 现状风险 | 建议 |
|----|----------|------|
| 并发 | 全局约 2 任务，多用户互相堵 | 按用户公平队列 + 可配置 `MAX_CONCURRENT` |
| 调度 | 内存 `activeTaskIds`，多实例会乱 | Redis / DB 分布式锁 |
| 磁盘 | 媒体默认保留 | `cleanup-media`、按用户配额、成功 N 天后只留 JSON |
| Whisper | 挂了要到转录步才失败 | 健康检查进前端 / 提交前预检 |
| LLM 降级 | soft fallback 可能被当成正常质量 | 标记「降级结果，建议重试」 |
| 工具路径 | yt-dlp / FFmpeg 写死本机路径 | 超管「环境检测」页 |

## 6. 建议产品迭代路线

### P0 — 体验打磨（约 1～2 周）

1. 断点重试（至少「只重总结」）  
2. 错误分类 + 可操作提示（Cookie / Whisper / 限流）  
3. 放宽「必须测模型」；排队位次展示  
4. 导出 SRT + Markdown  
5. Cookie / 登录态配置入口（抖音 / 小红书）  

### P1 — 多场景输出（约 2～4 周）

1. 本地上传  
2. 多平台二创模板  
3. 长文 Map-Reduce 总结  
4. 思维导图可视化  
5. 音频-only / 仅总结模式  

### P2 — 产品化与增长

1. 会员：时长 / 并发 / 模型档位  
2. 批量任务  
3. 闪卡 / 测验、分享链接  
4. 用量与成本看板（超管）  

---

## 7. 若只选 5 个「最划算」

1. **分步重试 / 只重 AI 总结** — 立刻省时间、降 LLM / 下载成本  
2. **本地上传 + 音频模式** — 场景从「能下的网课」扩到「所有音视频」  
3. **平台 Cookie 产品化** — 解决抖音 / 小红书「经常下不下来」  
4. **多模板二创** — 运营向用户感知最强  
5. **长视频分块总结** — 课程 / 播客不再「只懂头尾」

## 8. 与权限体系的衔接

当前角色：`USER`（普通用户）/ `MEMBER`（会员，充值预留）/ `SUPER_ADMIN`（超级管理员）。

| 能力 | USER | MEMBER（预留） | SUPER_ADMIN |
|------|------|----------------|-------------|
| 基础提取 | ✓ | ✓ | ✓ |
| 时长 / 并发 | 基础档 | 提高 | 不限或更高 |
| 高级模型 / 批量 | 限制 | ✓ | ✓ |
| 模型管理 / 用户管理 | | | ✓ |
| Cookie 全局代理（可选） | | | 配置 |

页面上 USER / MEMBER 暂不区分时，可先在 **后端配额** 落地，前端只在触顶时提示「升级会员」。

## 9. 推荐下一期落地方向

优先建议做 **P0** 中的：

1. **只重总结**（分步重试）  
2. **错误分类**  
3. **Cookie 配置**  

改动面可控，日常体验提升最明显。

方向二选一（产品侧重）：

- **运营二创**：多模板文案、批量链接、竖屏与封面帧  
- **学习 / 长视频**：Map-Reduce 总结、闪卡、导出笔记  

确定方向后可再拆具体接口与页面改动清单。
