# 个人知识库 · 模块导读

**包：** `com.dwcode.okxbot.kb`  
**入口：** `/api/v1/kb/*`  
**前端：** `okx-trading-web/src/views/kb/`  
**对照代码，不是 2026-07 那份规划。** 规划里「MVP 不做附件」已经过时。

附件分片细节见 [个人知识库_附件分片上传与断点续传.md](./个人知识库_附件分片上传与断点续传.md)。预览见 [个人知识库_富文本与附件预览方案.md](./个人知识库_富文本与附件预览方案.md)。本文：每个类干什么、核心请求怎么走、为什么拆成这样。

---

## 1. 这个模块在干什么

一人一份笔记库：文件夹树、标签、正文（HTML 或 Markdown）、附件、回收站、公开分享、导出、发到自己的 Halo 博客。

它**不是**异步 AI 任务。没有 Scheduler、没有槽位。请求进来，当前线程把事做完（附件分片除外：分片是多次 HTTP，合并仍在 complete 请求里做）。

检索：默认 `kb.search.mode=hybrid`（向量 + LIKE）。实现见 [Agent_LangGraph4j与知识库RAG.md](./Agent_LangGraph4j与知识库RAG.md)。密钥未配时自动 LIKE。

和视频提取的对比：

| | 视频提取 | 知识库 |
|--|----------|--------|
| 模型 | 异步任务 + 状态机 | 同步 CRUD |
| 重活 | 下载 / ASR / LLM | 大附件分片、PDF 打印、发博客 |
| 隔离 | `video_task.user_id` | 每张表 `user_id` |
| 存储 | 任务产物对象 | 笔记 LONGTEXT + 附件对象 |

## 2. 先建立一张图

```
/notes          笔记 CRUD、回收站、版本、导出
/categories     文件夹树
/tags           标签
/tree           资源管理器（夹 + 文档叶子，无正文）
/files          附件元数据、整包上传、内容流
/files/uploads  分片上传（PC 主路径）
/notes/{id}/share     登录用户开关分享
/public/s/{token}     不登录读公开笔记
/{id}/publish-blog    发 Halo（走 blog 包，不托管博客）
```

后端习惯：

```
Controller（薄） → 对应 *Service → Mapper / ObjectStorage / HaloPublishPort
```

一张笔记涉及几张表：`kb_note`、`kb_note_tag`、`kb_tag`、`kb_category`、`kb_file`、可选 `kb_note_revision`、`kb_file_upload`（上传过程中）。

## 3. 每个类做什么

DTO 是请求/响应壳，Mapper 是表访问，下面不逐个展开。

### 3.1 入口

| 类 | 路径前缀 | 做什么 |
|----|----------|--------|
| `KbNoteController` | `/api/v1/kb/notes` | 列表/详情/增改、软删/恢复/永久删、复制、版本、导出 md、导出 PDF、发博客。详情会打 `Server-Timing`（大正文慢在读库+序列化）。 |
| `KbCategoryController` | `/categories` | 文件夹树 CRUD。删除带 mode：`reject` / `orphan` / `trash`。 |
| `KbTagController` | `/tags` | 标签 CRUD。 |
| `KbExplorerController` | `/tree`、`/notes/batch-move` | 左侧资源管理器：整树、移动、同级重排、批量改文件夹。 |
| `KbFileController` | `/files` | 整包上传（≤100MB）、列表、元数据、内容流（Range）、绑定笔记、删除。 |
| `KbFileUploadController` | `/files/uploads` | 分片：init / 查进度 / PUT 片 / complete / abort。 |
| `KbShareController` | `/notes/{noteId}/share` | 开、关、换 token。 |
| `KbPublicShareController` | `/public/s/{token}` | **不登录**读公开笔记和附件。 |

Halo 站点绑定在 `blog` 包（`HaloBindingController`），不是 kb 包。发文时知识库只调用 `HaloPublishPort`。

### 3.2 配置

| 类 | 做什么 |
|----|--------|
| `KbProperties` | `kb.*`：正文长度、文件夹深度、搜索模式、附件上限/分片大小/并发闸、PDF 超时。 |

### 3.3 笔记 / 文件夹 / 标签 / 树

| 类 | 做什么 |
|----|--------|
| `KbNoteService` | 笔记主逻辑。保存时同时维护 `snippet`（列表摘要）和 `contentText`（纯文本，给搜索）。更新用 `UpdateWrapper` 且带 `is_deleted=0`，避免和软删打架。列表默认不返回正文。复制、导出 md、版本快照、回收站。 |
| `KbCategoryService` | 文件夹树，深度有上限。删夹三种策略：有内容拒绝、笔记变无分类、笔记进回收站。 |
| `KbTagService` | 标签；笔记-标签多对多（`replaceNoteTags`）。校验 tagId 必须是当前用户的。 |
| `KbExplorerService` | 把夹 + 笔记编成树给左侧栏。移动/重排改 `categoryId` + `sortOrder`，不碰正文。 |

### 3.4 附件

| 类 | 做什么 |
|----|--------|
| `KbFileService` | 整包 multipart 上传、列表、绑定 `noteId`、删对象、Range 输出内容。大文件不要走这里。 |
| `KbFileUploadService` | 分片会话。片落到 scratch，complete 时顺序拼接流式写入对象存储，再写 `kb_file`。 |
| `KbUploadLimiter` | 进程内闸门：每用户会话数、同时 PUT 数、全局合并数。超了 429。多实例不会共享。 |
| `KbUploadCleanupJob` | 定时清过期会话和 scratch。 |
| `SequentialFilesInputStream` | 按 `part-1, part-2, ...` 顺序读，合并时不当成一个巨大 `byte[]`。 |
| `KbFileRules` | 文件名清洗、类型、大小校验。 |
| `KbMediaTypes` | 预览时的 Content-Type；哪些可以 inline。 |

### 3.5 分享 / 博客 / PDF

| 类 | 做什么 |
|----|--------|
| `KbShareService` | 生成/轮换 `shareToken`。公开接口用 token 找笔记，不靠登录。正文里的私有附件 URL 换成公开文件地址。 |
| `KbBlogPublishService` | 把笔记副本发到用户绑定的 Halo。私有附件先传到 Halo 再换链接。失败只影响这次发布，知识库原文不动。 |
| `KbHaloContentRewriter` | 纯字符串替换：`/api/v1/kb/files/{id}/content` → Halo 公网 URL。 |
| `KbPdfExportService` | 接收前端排好的 HTML（或用已存正文），调无头 Chrome 打 PDF。 |
| `KbChromePdfRenderer` | 起 Edge/Chrome `--headless` 打印。 |
| `KbChromeLocator` | 找本机浏览器路径。 |
| `KbVuePdfDocument` | 把正文套进固定打印页（字体/CSS）。 |

### 3.6 表（Entity）

| 类 | 表 | 存什么 |
|----|-----|--------|
| `KbNoteEntity` | `kb_note` | 标题、正文、格式、摘要、检索文本、文件夹、置顶、软删、分享、Halo 弱引用 |
| `KbNoteRevisionEntity` | `kb_note_revision` | 历史版本（条数和最小间隔有限制） |
| `KbCategoryEntity` | `kb_category` | 文件夹树 |
| `KbTagEntity` | `kb_tag` | 标签 |
| `KbNoteTagEntity` | `kb_note_tag` | 笔记-标签 |
| `KbFileEntity` | `kb_file` | 附件元数据 + `objectKey` |
| `KbFileUploadEntity` | `kb_file_upload` | 分片会话：pending / completing / completed / aborted |

### 3.7 本模块会碰到、但不在 kb 包里

| 类 | 关系 |
|----|------|
| `SecurityUtils` | 所有登录接口先取 `userId`，再 `requireOwned`。 |
| `ObjectStoragePort` / `ObjectKeyBuilder` / `ScratchWorkspace` | 附件对象；分片临时目录。 |
| `HaloPublishPort` / `HaloBindingService` | 发博客；PAT 加密存在用户绑定表。 |
| `MediaRangeSupport` | 附件/分享附件的 Range。 |

## 4. 核心接口调用路径

### 4.1 打开知识库（读）

```
GET /api/v1/kb/tree
  → KbExplorerService.tree
  → 当前用户的文件夹 + 笔记叶子（无 content）

GET /api/v1/kb/notes?page&size&categoryId&tagId&keyword...
  → KbNoteService.list
  → 过滤软删、分页；命中用 title / content_text LIKE
  → 返回 snippet，不返回正文

GET /api/v1/kb/notes/{id}
  → 读一整篇 + 标签
  → 大正文慢：LONGTEXT + JSON，不是排队
```

### 4.2 写一篇笔记

```
POST /notes          新建：插 kb_note，写标签，维护 snippet / content_text
PUT  /notes/{id}     更新：条件更新（必须仍是未删除）
                     正文变更可能打一条 revision（有间隔和条数上限）

删除：
  DELETE /notes/{id}            软删 → 回收站
  POST   /notes/{id}/restore    恢复
  DELETE /notes/{id}/permanent  删行 + 该笔记附件对象
  DELETE /notes/trash           清空回收站
```

前端自动保存走 PUT。列表和树不带正文，就是为了自动保存时不要每次把整库笔记内容拉回来。

### 4.3 附件：PC 分片（主路径）

```
POST   /files/uploads                         建会话，返回 chunkSize / totalParts
PUT    /files/uploads/{id}/parts/{n}          流式写入 scratch/part-n（已存在则幂等）
GET    /files/uploads/{id}                    receivedParts → 断点续传
POST   /files/uploads/{id}/complete           CAS 合并 → ObjectStorage → kb_file
DELETE /files/uploads/{id}                    取消

笔记尚未保存：
  init 时 noteId 为空 → 完成后前端拿 fileId
  笔记保存成功 → POST /files/{fileId}/bind
```

小程序：`POST /files` multipart，上限 100MB。

预览/下载：`GET /files/{id}/content`（可 `Range`，可 `?download=true`）。这是**下载**续传，不是上传断点。

### 4.4 文件夹树操作

```
POST /tree/move         夹或笔记改父文件夹
POST /tree/reorder      同级 sortOrder
POST /notes/batch-move  多篇改文件夹
DELETE /categories/{id}?mode=reject|orphan|trash
```

Explorer 不加载正文，所以拖拽移动是轻操作。

### 4.5 公开分享

```
登录：
  POST /notes/{id}/share          生成 token，share_enabled=1
  POST /notes/{id}/share/rotate   旧链接作废
  DELETE /notes/{id}/share        关闭

任何人：
  GET /public/s/{token}                      读笔记（正文里的附件地址已换成公开路径）
  GET /public/s/{token}/files/{fileId}/content
```

公开接口**没有** JWT。安全靠 token 够长、可轮换；不靠「隐藏 URL」。

### 4.6 发 Halo / 导出

```
GET  /notes/{id}/publish-blog     拉 Halo 分类标签等选项（用用户自己的绑定）
POST /notes/{id}/publish-blog     KbBlogPublishService
                                    读笔记 + 附件
                                    附件 upload 到 Halo，正文换链接（不改 kb_note.content）
                                    HaloPublishPort 发文
                                    只回写 haloPostName / permalink / publishedAt

GET  /notes/{id}/export?format=md
POST /notes/{id}/export-pdf       前端把当前排版 HTML 发来 → 无头 Chrome
```

发博客走 `blog` 包。超管用平台 PAT；普通用户必须自己绑站点，禁止回落到平台令牌。

## 5. 为什么这么设计

**同步 CRUD，不上任务表。** 笔记保存是用户等结果的交互；没有「排队 10 分钟」。硬套视频那套 Scheduler 只会更绕。PDF / 发博客偶发较慢，但仍是一次请求做完，没有做成异步任务（PDF 超时有上限）。

**列表与详情分离。** 正文是 LONGTEXT。列表、树、搜索只碰 `snippet` / `content_text` / 标题。否则打开左侧栏就会把所有笔记正文读进 JVM。

**所有查询带 userId。** 和 chat/video 同一套：登录用户从 JWT 取 id，再 `requireOwned`。分享是显式的另一条公开 API，不是「列表接口加个 flag」。

**附件两条路径。** Spring multipart 大约 110MB，JVM 也不适合接 2GB。PC 走分片 + scratch + 流式 complete；小程序 API 简单，继续整包。会话进度以磁盘上完整分片为准，不把进度字段当权威，避免并发 PUT 打脏。

**知识库不托管博客。** Halo 是外部站。发的是副本，原文仍私有。绑定和发文失败不影响笔记。这是产品边界，不是没做完。

**版本是抽样快照，不是 Git。** 自动保存很勤，每键都存版本会爆表。所以有最小间隔和条数上限。

**搜索先 LIKE。** 配置里留了 fulltext，默认 like，零运维。数据量变大再切，现在没有 ES。

**Limiter / 上传闸门单机即可。** 和视频槽位同一类选择：当前就一台 Java。文档里写清楚，避免面试时说成已经分布式。

## 6. 不要和这些搞混

| 容易混 | 实际 |
|--------|------|
| 规划文档 Phase 1「不做附件」 | 附件和分片已经在线上代码里 |
| 分片 PUT vs content Range | 一个是上传，一个是预览/下载 |
| `kb_file_upload` vs `kb_file` | 前者是进行中的会话，complete 成功才有后者 |
| Halo 附件 vs 知识库附件 | 发文时复制到 Halo；知识库对象还在 |
| 小程序上传 vs PC | 小程序整包；PC 全部分片 |
