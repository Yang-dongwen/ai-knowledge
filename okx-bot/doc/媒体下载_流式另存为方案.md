# 媒体下载 · 浏览器原生流式另存为

**日期**：2026-09-09  
**状态**：已落地（PC Web + 后端代理 / R2 预签名）  
**范围**：视频提取、AI 成片、文生图、知识库附件的「另存为」与大媒体预览  
**代码**：`okx-bot` 媒体代理 / `MediaUrlService`；`okx-trading-web/src/utils/download.ts`

---

## 1. 问题

用户点「下载」后要等整文件进入浏览器内存，系统下载栏才出现。大视频（提取任务、成片）卡很久，并占满 JS 堆。

根因在**前端整包拉取**，不是存储层没有流。后端多数接口早已按 `InputStream` 写出；播放路径（`<video src>` + HTTP Range + R2 预签名）已经是流式。只有「另存为」走了：

```
resolveDownloadUrl → fetch(url) → arrayBuffer() → Blob → <a download>
```

`arrayBuffer()` 会等响应体全部到达。

---

## 2. 原则

1. **另存为不进 JS 堆**：只请求很小的鉴权 JSON（media-url），再用浏览器原生下载写盘。
2. **R2 预签名优先**：流量不经应用进程；local / 预签名失败回退同源代理。
3. **代理必须能 Range + attachment**：`<video>` 边下边播；`<a download>` 强制另存为。
4. **query JWT 仅媒体 GET**：与现有 `<video src>` 同一白名单，不扩大到非媒体路径。
5. **生成物不假装流式**：笔记 MD/PDF 必须先渲染完整字节，保持 `byte[]` + blob。

---

## 3. 目标路径

```
点击下载
  → GET .../media-url?disposition=attachment   （鉴权 JSON，很小）
  → presign 直链  或  /api/.../video?download=true&access_token=...
  → triggerNativeDownload(url, filename)       （立刻 <a.click>）
  → 浏览器分块拉流写盘，不进 JS 堆
```

| 模式 | URL | 鉴权 | 文件名 |
|------|-----|------|--------|
| `presign` | R2 预签名 HTTPS | 签名 query | 预签名里的 `Content-Disposition: attachment` |
| `proxy` | 同源 `/api/v1/...` | `?access_token=`（媒体 GET 白名单） | 响应头 + 同源 `download` 属性 |

播放仍走 `disposition=inline` 的 media-url，赋给 `<video src>`，**不要**再 `fetch` 成 blob。

---

## 4. 入口盘点

| 入口 | 改前 | 改后 |
|------|------|------|
| 视频提取「下载视频」 | `fetchVideoBlob` → `arrayBuffer` | `resolveVideoDownload` + `triggerNativeDownload` |
| AI 成片「下载」 | `fetchOutputBlob` → `arrayBuffer` | `resolveOutputDownloadUrl` + 同上 |
| 文生图「下载」 | 用展示用 blob/预签名 | `resolveImageDownloadUrl`（`attachment`） |
| 知识库附件下载 | `window.open(?download=true)` | 同源 `<a download>`（已流式，避免弹窗拦截） |
| 知识库图 / 视频 / PDF 预览 | `fetchArrayBuffer` 整包 | 直接 `kbMediaUrl`（视频可靠 Range） |
| 知识库 docx / xlsx 预览 | `arrayBuffer` | **保持**（解析器需要完整缓冲） |
| 笔记导出 MD / PDF | axios blob；后端 `byte[]` | **保持**（必须先生成完整文档） |
| 小程序 `wx.downloadFile` | 系统下载 | **不改** |

## 5. 前端

### 5.1 公共工具

`okx-trading-web/src/utils/download.ts`

- `triggerNativeDownload(url, filename)`：不 `fetch` 正文。同源设 `download`；跨域预签名依赖响应头（浏览器会忽略跨域 `download` 属性）。
- `safeDownloadName`：去掉路径非法字符，补扩展名。

`attachAccessTokenIfProxy`（`video.api.ts`）：proxy 相对路径补 `access_token`，播放与下载共用。

### 5.2 API

| 模块 | 下载 URL | 播放 URL | 代理回退 |
|------|----------|----------|----------|
| video | `GET /v1/video/tasks/{id}/media-url?disposition=attachment` | 同路径 `inline` | `/api/v1/video/tasks/{id}/video?download=true` |
| aigen | `GET /v1/aigen/tasks/{id}/media-url?disposition=attachment` | 同路径 `inline` | `/api/v1/aigen/tasks/{id}/media/output?download=true` |
| imggen | `GET /v1/imggen/tasks/{id}/media-url?fileName=&disposition=attachment` | `inline` | `/api/v1/imggen/tasks/{id}/media/{file}?download=true` |
| kb | 已有 `GET /v1/kb/files/{id}/content?download=true` | 无 `download` | `kbMediaUrl` 已带 token |

已删除：`fetchVideoBlob`、`fetchOutputBlob`。

缩略图 / 画廊仍可用小图 blob（`fetchShotImageBlob` / `fetchImageBlob`），体量小，与另存为无关。

## 6. 后端

### 6.1 media-url 与代理 query

`MediaUrlService.resolve(..., attachment, downloadName)`：

- `attachment=true` 时 R2 `presignGet` 带 `Content-Disposition: attachment; filename*=UTF-8''...`
- 同时给 **proxyPath / proxy url** 追加 `?download=true`（已有则不重复），供前端回退

代理 GET 识别 `?download=true`：

| 路径 | 方法 |
|------|------|
| `GET /api/v1/video/tasks/{id}/video?download=true` | `VideoProcessService.downloadVideo(..., download)` |
| `GET /api/v1/aigen/tasks/{id}/media/output?download=true` | `AigenTaskService.openOutputMedia(..., download)` |
| `GET /api/v1/imggen/tasks/{id}/media/{file}?download=true` | `ImgGenTaskService.openMedia(..., download)` |
| `GET /api/v1/kb/files/{id}/content?download=true` | `KbFileService.streamContent`（原已有） |

无 `download` 时 `Content-Disposition: inline`（播放 / 预览）。

**视频提取另存为不转码**：`disposition=attachment` 与 `?download=true` 走 `resolveDownloadableVideo`——用 yt-dlp 源片（`video.mp4` / `video.webm`），即使 `videoPath` 已指向 `video.browser.mp4`。不调用 `ensureBrowserPlayable`，不从 R2 拉回整片转 H.264。播放（`inline`）仍可懒转码。

### 6.2 Range

`MediaRangeSupport.build(range, size, contentType, filename, openRange, attachment)`：

- 无 Range → 200 + `Accept-Ranges: bytes`
- 有 Range → 206 + `Content-Range`
- 匿名 `InputStreamResource` **必须覆盖 `contentLength()`**，否则 Spring `ResourceHttpMessageConverter` 会把整段流读进内存（子类不等于 `InputStreamResource.class`，不会走「跳过测长」分支）

统一工厂：`MediaRangeSupport.streamingResource`、`contentDisposition`。

知识库视频（私有流 + 公开分享流）走同一套 Range；图片 / PDF 仍 200 + `Content-Length`。

### 6.3 鉴权

`JwtAuthFilter.MEDIA_QUERY_TOKEN_PATH` 仅允许这些 GET 带 `access_token`：

- `/api/v1/kb/files/{id}/content`
- `/api/v1/video/tasks/{id}/video`
- `/api/v1/aigen/tasks/{id}/media/output`
- `/api/v1/aigen/tasks/{id}/shots/{id}/image`
- `/api/v1/imggen/tasks/{id}/media/{file}`

公开分享 `/api/v1/kb/public/s/{token}/files/{id}/content` 不需要 JWT。

## 7. 网关

- nginx `/api/`：已 `proxy_buffering off`，不动。
- Caddy（`deploy/stack/Caddyfile`，`dwcode.cloud`）：`encode gzip` **只匹配** `text/*`、`application/json*`、`application/javascript*`、`application/xml*`、`image/svg+xml*`，避免压 mp4 / octet-stream 拖慢首包。

Vite 开发代理默认透传流，无需改。

## 8. 明确不改

| 项 | 原因 |
|----|------|
| `GET/POST /api/v1/kb/notes/{id}/export`、`export-pdf` | Chrome/PDF 渲染必须得到完整文档 |
| docx / xlsx 预览 | `docx-preview` / SheetJS 要 `ArrayBuffer` |
| 小程序下载 | `wx.downloadFile` 已是系统流 |

---

## 10. 风险

| 风险 | 处理 |
|------|------|
| 跨域 `<a download>` 被忽略 | R2 预签名写入 `Content-Disposition` |
| `access_token` 进访问日志 / Referer | 仅媒体 GET 白名单，与 `<video src>` 相同 |
| 弹窗拦截 | 用户点击栈里同步 `a.click()`，不用 `window.open` |
| Spring 读尽 `InputStream` | 匿名 Resource 覆盖 `contentLength` |
