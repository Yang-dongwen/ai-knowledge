# 个人知识库 · 附件上传与断点续传

**对照代码：** 当前 `okx-bot` + `okx-trading-web` 实现，不是规划文档里的「拟」  
**面试口述：** 本文 §7；追问库见 [面试题_AI工具台_面试官视角.md](./面试题_AI工具台_面试官视角.md) §11

---

## 1. 要解决什么

知识库附件要支持图片、PDF、Office、视频，单文件最大 **2GB**。整包 `multipart` 会同时踩三块：

1. **网关 / Spring** `multipart.max-file-size`（现网 110MB）接不住大文件  
2. **JVM 内存**：整文件进 `MultipartFile` 容易撑爆  
3. **弱网 / 刷新 / 暂停**：传了一半断了，必须能从已落盘分片继续，而不是从头再传

所以做成两条路径：

| 路径 | 上限 | 谁在用 | 为什么还留 |
|------|------|--------|------------|
| 整包 `POST /api/v1/kb/files` | 100MB（`kb.file.max-direct-bytes`） | 小程序、兼容旧客户端 | 小文件一次请求更简单；小程序 `wx.uploadFile` 走 multipart |
| 分片 ` /api/v1/kb/files/uploads/*` | 2GB（`kb.file.max-bytes`） | PC 端 `kbApi.uploadFile` **唯一路径** | 流式、可暂停、可续传、绕开 multipart 上限 |

PC 端现在**不再走整包**。富文本插图、附件面板、Markdown 拖图，全部进分片客户端。

## 2. 整体方案（一句话）

> **会话在 DB，分片在本地 scratch，成片进对象存储。**  
> 前端按 `uploadId` 查已收分片，只 PUT 缺的片；合并用 CAS 防双完成；过期定时清 scratch。

```
浏览器 File
    │  slice(start, end)  默认 8MB/片，并发 3
    ▼
POST /uploads                 建会话 kb_file_upload（pending, TTL 24h）
PUT  /uploads/{id}/parts/{n}  流式写入 scratch/kb/up{id}/part-n
GET  /uploads/{id}            返回 receivedParts → 断点续传
POST /uploads/{id}/complete   CAS pending→completing → 顺序拼接 → ObjectStorage
DELETE /uploads/{id}          取消：删 scratch + 会话
    ▼
kb_file 元数据（object_key）
    │
GET  /files/{id}/content      预览/下载（可带 Range，这是下载续传，不是上传）
POST /files/{id}/bind         先传后绑笔记（未保存笔记时）
```

存储分层：

| 层 | 存什么 | 生命周期 |
|----|--------|----------|
| MySQL `kb_file_upload` | 会话：文件名、总大小、片大小、片数、状态、过期时间 | 完成/取消/过期后删 |
| 本地 scratch `scratch/kb/up{uploadId}/part-{n}` | 原始分片字节 | complete / abort / 定时任务清理 |
| MySQL `kb_file` | 附件元数据 | 用户删附件或笔记永久删除 |
| `ObjectStoragePort`（本地盘 / R2） | 完整对象 `env/kb/{userId}/{fileId}/{name}` | 与 `kb_file` 同生共死 |

**刻意没做的：** 没有直接调 S3 Multipart Upload。分片先落本机再一次 `putStream`。R2 侧自己的 multipart 阈值（8MB）是对象存储适配器内部的事，对知识库 API 不可见。

## 3. 接口清单

前缀均为 `/api/v1/kb`。除 content 流外，统一 `ApiResult`。全部要登录，且按 `userId` 隔离。

### 3.1 分片会话（断点续传主路径）

`KbFileUploadController` → `KbFileUploadService`

| 方法 | 路径 | 作用 | 关键入参 / 出参 |
|------|------|------|-----------------|
| `POST` | `/files/uploads` | 初始化会话 | 入：`originalName, sizeBytes, contentType?, noteId?`  
出：`uploadId, chunkSize, totalParts, status, receivedParts, expiresAt` |
| `GET` | `/files/uploads` | 未完成会话列表（刷新页面恢复「暂停」） | `noteId` 或 `unbound=true`（尚未绑笔记） |
| `GET` | `/files/uploads/{uploadId}` | 查进度，**续传入口** | 出：`receivedParts`（1-based 已落盘片号）、`uploadedBytes` |
| `PUT` | `/files/uploads/{uploadId}/parts/{partNumber}` | 上传一片 | Body：`application/octet-stream`；校验 `Content-Length` = 期望片大小 |
| `POST` | `/files/uploads/{uploadId}/complete` | 合并成附件 | 出：`FileResponse`（含 `contentPath`） |
| `DELETE` | `/files/uploads/{uploadId}` | 取消 | 已 completed / completing 拒绝 |

片号从 **1** 开始。非末片大小 = `chunkSize`（默认 8MB）；末片 = 余数。

### 3.2 附件实体（上传完成后的生命周期）

`KbFileController` → `KbFileService`

| 方法 | 路径 | 作用 |
|------|------|------|
| `POST` | `/files` | 整包 multipart，上限 100MB（小程序） |
| `GET` | `/files?noteId=` | 某笔记附件列表 |
| `GET` | `/files/{id}` | 元数据 |
| `GET` | `/files/{id}/content` | 在线流；`?download=true` 下载；支持 `Range` |
| `POST` | `/files/{id}/bind` | 把「先上传、后保存笔记」的附件绑到 `noteId` |
| `DELETE` | `/files/{id}` | 删元数据 + 对象 |

### 3.3 前端封装（PC）

`okx-trading-web/src/api/kb.api.ts`

| 方法 | 实际打哪些接口 |
|------|----------------|
| `kbApi.uploadFile(file, noteId, { resumeUploadId, onProgress, signal })` | GET 会话（若有 id）→ 否则 POST init → 并发 PUT 缺片 → POST complete |
| `kbApi.listUploads({ noteId, unbound })` | `GET /files/uploads` |
| `kbApi.abortUpload(uploadId)` | `DELETE /files/uploads/{id}` |
| `kbApi.listFiles / bindFile / deleteFile` | 对应 3.2 |

UI：`FilePanel.vue`（暂停 / 继续 / 取消、刷新后从 `listUploads` 拉回暂停列表）。

## 4. 状态机

`kb_file_upload.status`：

```
          init
            │
            ▼
        pending  ←──────── complete 失败 CAS 回滚
            │
            │  CAS pending → completing
            ▼
       completing ──成功──► completed（fileId 已有，complete 再调幂等返回同一文件）
            │
 abort      │ 过期清理
            ▼
        aborted → 立刻物理删除行 + scratch
```

约束：

- **PUT 分片**只接受 `pending`
- **complete** 只从 `pending` CAS 进 `completing`；已 `completed` 再调返回已有 `kb_file`
- **abort** 拒绝 `completed` / `completing`（合并中不能取消）
- 过期（默认 24h）：`pending` 再访问返回 **410**；定时任务 15 分钟扫过期行，清 scratch、未完成的还要 `releaseSession`

## 5. 断点续传怎么做成的

断点续传 = **「已成功落盘的分片不再传」**，不是 HTTP Range 上传。

### 5.1 服务端

1. 每片写到 `part-{n}`，先写 `part-n.tmp.{uuid}` 再 `ATOMIC_MOVE`，避免半片被当成完成  
2. 片已存在且 `size == expected`：排空请求体，直接当成功（**幂等 PUT**）  
3. `GET` / 每次 PUT 响应都带 `receivedParts` + `uploadedBytes`，以 **磁盘实况** 为准，不把进度存在 DB 字段里（避免并发写进度打架）

### 5.2 客户端

1. **指纹**：`sessionStorage["kb-upload:{name}:{size}:{mtime}:{noteId}"] = uploadId`  
2. 再次上传同一文件：先 `GET /uploads/{id}`，`status===pending` 才续；否则重新 init  
3. 用 `receivedParts` 算出 missing，工人池并发 PUT（前端并发 3；后端用户级 6 / 全局 16）  
4. **暂停**：`AbortController.abort('pause')`，会话和 scratch 保留  
5. **取消**：abort + `DELETE` 会话  
6. **刷新页面**：`listUploads` 把 pending 渲染成暂停行；内存里还握着 `File` 就能直接继续，否则提示「选择同一文件继续」（浏览器不允许页面关闭后还读原 File）

### 5.3 和「下载 Range」不要混

| | 上传断点续传 | 内容 Range |
|--|-------------|------------|
| 接口 | PUT parts + GET session | `GET /files/{id}/content` + `Range` |
| 目的 | 大文件传完 | 视频 seek、PDF 边下边显、另存为 |
| 状态 | `kb_file_upload` + scratch | 已存在的对象 |

面试被追「Range 上传」时：本方案是 **应用层分片**，不是 RFC 7233 的 PUT Range。

## 6. 关键设计（面试常追这里）

### 6.1 控内存

- PUT 用 `HttpServletRequest.getInputStream()`，**64KB 缓冲**拷到盘，不进 `byte[]` 整片  
- complete 用 `SequentialFilesInputStream` 按片顺序流式 `objectStorage.putStream`，不把 2GB 拼进堆  
- 整包路径才受 Spring multipart 限制，所以大文件必须走分片

### 6.2 幂等与并发

- 同一分片并发 PUT：先完成的原子改名，后到的发现完整片就丢弃临时文件  
- complete：`UPDATE ... WHERE status='pending'` CAS，输的一方 409  
- complete 失败：删刚插入的 `kb_file`、尽力删对象，CAS 回 `pending`，用户可补片再 complete  
- complete 成功后再调：直接返回已有文件（防前端重试造双附件）

### 6.3 限流闸门（`KbUploadLimiter`，单进程）

| 闸 | 默认 | 超限 |
|----|------|------|
| 每用户同时会话 | 3 | 429 |
| 每用户同时 PUT | 6 | 429 |
| 全局同时 PUT | 16 | 429 |
| 全局同时 complete | 2 | 429（合并吃磁盘/带宽） |

多实例时这份 Semaphore **不会共享**，要扩实例得改成 Redis / 分布式信号量。和任务槽位是同一类边界，面试主动说。

### 6.4 先传后绑笔记

新建笔记还没保存就拖文件：`noteId` 为空 init。完成后前端拿 `fileId`，笔记保存成功再 `POST /files/{id}/bind`。  
`listUploads(unbound=true)` 用来恢复「未绑笔记」的暂停会话。

### 6.5 安全

- 会话 / 附件 `requireOwned(userId)`，别人猜 `uploadId` 是 404  
- 文件名 `sanitizeOriginalName`，对象 key 用安全名  
- 片大小必须精确匹配，防声明 8MB 实际灌任意长度  
- 总量 / 片数上限：2GB、最多 512 片

### 6.6 配置（`config/platform.yml` → `kb.file`）

```
max-bytes: 2GB
max-direct-bytes: 100MB
chunk-size-bytes: 8MB
max-parts: 512
session-ttl-hours: 24
max-sessions-per-user: 3
max-concurrent-parts-per-user: 6
max-concurrent-parts-global: 16
max-concurrent-complete-global: 2
cleanup-cron: 每 15 分钟
```

Spring `multipart.max-file-size: 110MB` 只罩整包路径。

## 7. 面试怎么答

分清两段经历，不要混成一套系统：

| 简历条目 | 事实边界 |
|----------|----------|
| **AIFactory 语料大文件** | 华为项目：分片 + 流式 + 断点续传 + Nginx 反代云端语料；量级是平台语料，不是这个站 |
| **知识库附件** | 独立项目现网代码，可画接口、可讲状态机；单机、自用、没有百万上传 QPS |

被问「你做过断点续传」：先用知识库把协议讲清楚（可验证），再补一句 AIFactory 是同类问题在更大语料规模上的落地。

### 7.1 60 秒骨架（优先背这个）

> 知识库附件 PC 端全走分片：先 `POST` 建上传会话，服务端按 8MB 切好片数，TTL 24 小时。  
> 前端 `File.slice` 并发 PUT 原始字节流，服务端流式落到 scratch，已存在且大小对的片直接幂等成功。  
> 刷新或暂停后 `GET` 会话拿 `receivedParts`，只补缺片。全部到齐 `complete`：CAS 把状态从 pending 打到 completing，顺序拼接流式写入对象存储，再写 `kb_file`。  
> JVM 里始终只有一块缓冲区，不把整文件读进内存。取消删 scratch；过期定时清。  
> 小程序仍走 100MB 整包，因为 `wx.uploadFile` 是 multipart。

### 7.2 高频追问

**Q：为什么不直接 S3 Multipart？**  
Scratch + 一次 put，实现和本地存储 / R2 都能走同一 `ObjectStoragePort`。R2 Adapter 内部超过阈值会自己分片，业务 API 不用绑死 S3 协议。代价是合并时本机要有完整文件的临时空间。

**Q：进度存在哪？崩溃会不会丢片？**  
进度以 scratch 目录里完整 `part-n` 为准。进程重启：会话还在 DB，片还在盘，GET 能扫出来。没原子改名成功的 `.tmp` 不算已收。

**Q：暂停和取消的差别？**  
暂停只掐前端 AbortSignal，服务端会话仍 pending。取消才 DELETE，释放会话配额。合并中（completing）不能取消，避免对象写到一半被拆。

**Q：并发上传同一片？**  
允许。完整片检测 + 临时文件 + 原子移动。测过同片多线程 PUT 仍能 complete。

**Q：complete 调两次？**  
第一次 CAS 成功落 `kb_file`；第二次发现已 completed 且 fileId 在，直接返回同一文件，不会复制对象。

**Q：和任务系统暂停有何不同？**  
任务暂停是协作式看步骤边界；上传暂停是 HTTP 连接级 abort，已落盘片保留。不要说「上传也是状态机步进」。

**Q：多实例？**  
Limiter 和 scratch 都在单机。两台 Java 会：会话配额算不准、分片可能落在另一台盘上、complete 找不到片。要扩实例，scratch 得换共享盘或直接云 multipart，闸门上 Redis。现在规模用不上。

**Q：2GB 会不会打满磁盘？**  
有会话数、并发 complete、TTL、定时清理。仍可能被同一用户在 TTL 内占满（3 × 2GB scratch）。这是已知容量风险，不是「已经无限流」。

**Q：AIFactory 那条怎么接？**  
那边是语料平台，问题同样是「大文件 + 弱网 + 不能撑爆 JVM」。手段同类：分片、流式、续传；另外用 Nginx 反代解决云端语料跨域和大文件访问。不要把知识库的 2GB / 8MB 片说成华为平台的数字。

### 7.3 别说

- 「我们实现了 HTTP Range 上传」  
- 「已经对接 S3 Multipart 三步协议」  
- 「多实例也能断点续传」（scratch 在本地）  
- 「进度存在 Redis」  
- 把知识库上传 QPS / 日活说成 AIFactory 百万语料

## 9. 和预览 / 下载的交界

上传完成只保证对象在存储里。预览、另存为、视频拖进度走另一套：`GET /files/{id}/content` + Range + 前端按 `kind` 选 img/video/pdf/docx。见富文本与附件预览方案。发 Halo 博客时会把私有附件再传到 Halo 换公网链接，失败不影响知识库原文。
